Chain of Custody: how each rule is enforced

The model reasons about evidence. It never holds the authority to change it. Every arrow below is a separate check.

verified live

Amazon Bedrock AgentCore managed harness

  • Claude Sonnet 4.6, temperature 0, 12 iterations max, memory off
  • allowedTools: @evidence only: no shell, files, web or sub-agents
  • Execution role: one model, one Gateway, no role switching, no direct commands
SigV4, signed as the harness execution role
verified live

AgentCore Gateway + policy engine (Cedar, ENFORCE)

  • Boundary: only the harness role, only this gateway (an admin role was denied live)
  • One permit per tool, with argument constraints: case evidence IDs, cited evidence, provenance
  • Anything else: denied by default, before the backend runs
tool name and Gateway request ID; arguments untrusted
verified live

Tool Lambda: the domain core

  • Deny-by-default policy; the agent gets 4 operations: read metadata, read originals, record a finding, draft a proposal
  • Closed schemas; content rule refuses conclusions of guilt or blame
  • Identity and case from deployment configuration, never from arguments
  • Every call audited: durable, append-only, attributed to the agent
  • IAM: DynamoDB writes limited to 3 logical tables, no evidence writes, updates or deletes (template-tested)
conditional writes, exact-version reads

DynamoDB ledger

  • Hash-chained, append-only events
  • Corrections append; originals stay
  • Signed checkpoints: local app

S3 evidence

  • Object Lock, create-only
  • Read by exact version only

Write-once archive

  • Every event and audit record (verified live)
  • Tamper alarm (tested locally)
local app

People, in the workspace

  • Promote or dismiss the agent's drafts (both kept)
  • Record custody, claims, corrections
  • Exports need a different supervisor; single use
  • Supervisors read the security log
offline

Independent verifier

  • Checks an export against a separately delivered key and ledger head
  • Proves integrity, not authenticity

What an attack has to get past

  1. The harness tool allowlist
  2. IAM on every role
  3. Cedar at the Gateway
  4. The domain core's own checks
  5. A person, for anything that changes the record

"Verified live": exercised on AWS on November 19, 2026, then torn down. "Local": the investigation workspace and the offline verifier run on the developer's machine. All case data is synthetic.
